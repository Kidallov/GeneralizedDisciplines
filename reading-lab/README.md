## Просмотр и экспорт в Visual Studio Code

Откройте папку проекта в VS Code и установите рекомендуемое расширение **PlantUML** (идентификатор `jebbs.plantuml`). Для локального рендеринга требуется Java. Откройте любой файл `.puml` и вызовите команду **PlantUML: Preview Current Diagram**. Для экспорта используйте **PlantUML: Export Current Diagram** и выберите SVG. Файл `style.iuml` должен оставаться рядом с диаграммами.

Изображения комплекта построены локально с помощью PlantUML 1.2024.3 из расширения VS Code 2.18.1. Названия классов, полей и состояний даны на английском для прямого переноса в Python.

## Генерация и запуск

В терминале из папки проекта выполните команды с Python 3.10 или новее. Для генерации и демонстрации достаточно стандартной библиотеки.

```console
python generate.py
python generate.py --check
python demo.py
```

[Генератор](generate.py) читает объявления из диаграммы классов и записывает [Python-модель](model.py). Обычные классы становятся типами данных `dataclass`, перечисление состояний становится `Enum`, интерфейсы становятся `Protocol`. Типы полей и сигнатуры операций переносятся из исходника. Связи, у которых есть соответствующее поле, представлены ссылками на объекты, списками или необязательной ссылкой. Ограничение «один или более вопросов» также проверяется при расчёте.

Генератор рассчитан на синтаксис объявлений данной модели. Поля и методы редактируются в `uml/02_classes.puml`, затем `model.py` создаётся заново. Команда `--check` сравнивает файл с ожидаемым результатом. Реализация расчётов находится в [scoring.py](scoring.py), учебный сценарий — в [demo.py](demo.py).

## Контрольный пример

Ребёнок читает текст «Утром Маша увидела у крыльца ежа. Ёж спрятался под кустом». В учебной записи длительностью 15 секунд пропущено слово «Утром». Демонстрационный распознаватель подставляет слово «ерша» вместо «ежа». После сверки педагог восстанавливает «ежа» и сохраняет реально произнесённые девять слов. Запись, подтверждение педагога и выбор вариантов смоделированы входными данными. Для интеграции речевой модели предусмотрен интерфейс `Recognizer.transcribe`.

| Показатель | Расчёт | Результат |
| --- | --- | --- |
| Расхождения с эталоном | Минимальное суммарное число вставок, пропусков и замен слов в подтверждённой расшифровке | 1 на 10 слов эталона |
| Темп | 9 произнесённых слов × 60 / 15 секунд записи | 36 слов/мин |
| Понимание прочитанного | На вопрос «Кого увидела Маша?» выбран ответ «Ежа». На вопрос «Куда спрятался ёж?» выбран ответ «Под крыльцо» при ключе «Под куст» | 1 из 2 |

При сравнении слова приводятся к нижнему регистру, «ё» и «е» считаются равными, знаки препинания игнорируются. Дефис внутри слова сохраняется. Темп учитывает паузы в пределах всей записи. Результаты относятся к данному заданию. Учебный пример иллюстрирует расчёт и не используется для выводов о качестве распознавания детской речи.
